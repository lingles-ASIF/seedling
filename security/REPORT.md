# Seedling — Security Review of the Rust Growth Engine

**Date:** 2026-11-12  **Scope:** `src/lib.rs` (engine), `Cargo.toml`, and the host page `web/template.html` / `seedling.html`.
**Result:** 21 of 21 checks pass (100%).

The score is the share of checks in the list below that pass. It is not an
industry-standard rating or a third-party certification: no such standard
percentage exists. Every check can be re-run with the commands at the end.

## Findings and fixes

| # | Finding | Severity | Fix |
|---|---|---|---|
| 1 | Calling `tick` before `init` underflowed an unsigned index and crashed the engine (trap). | Medium (crash) | `tick` returns an empty draw list until `init` has run. |
| 2 | One NaN or ±Infinity input (or a coordinate so large its square overflowed) corrupted the stored state permanently; every later frame drew garbage. | Medium (persistent corruption) | All inputs sanitized and clamped at the boundary; a self-heal resets the plant if state ever goes non-finite. |
| 3 | `world()` was a *safe* function returning `&'static mut`; calling it twice would be undefined behavior. | Low (latent unsoundness) | Now an `unsafe fn` with a written safety contract; each export calls it exactly once, with a `SAFETY:` comment. |
| 4 | Release builds wrapped on integer overflow instead of stopping. | Low (hardening) | `overflow-checks = true` in the release profile. |
| 5 | The page had no Content Security Policy. | Low (hardening) | Hash-pinned CSP generated by `build.py`: only the page's own script and style may run; no network. |
| 6 | Long runs would slowly lose precision in the animation clock (after weeks). | Informational | Clock wraps every 10,000 s. |
| 7 | Clippy: approximate π constant (default-level error) and 20 pedantic cast warnings. | Informational | Uses `core::f32::consts`; every cast made explicit with a stated bound. |

A behavior bug turned up during testing too: the retreat to the seed slowed as the
stem shortened (~2.5 s instead of ~1.2 s). It is fixed; it was not a security issue.

4. Every `unsafe` block justified (`undocumented_unsafe_blocks` set to deny): pass. One `unsafe fn`, four call sites, all documented.

8. No permanent state corruption after hostile input: pass
9. Calls before `init` are safe: pass

11. Grows, blooms and withers with zero errors and zero CSP violations: pass

13. Code-from-strings (the eval family) is blocked: pass

**Design and configuration**

15. Zero third-party dependencies (nothing to audit in the supply chain): pass

17. `panic = "abort"` (no unwinding paths): pass
18. No heap allocator; fixed-size buffers, so memory use can't grow: pass

## Residual risk (accepted, not failures)

- One `unsafe` remains. Single global state in `no_std` Rust needs it; it is confined to one function with a written contract.
- The CSP must allow `'wasm-unsafe-eval'`. That is the narrowest permission that lets a page compile WebAssembly; it does not allow JavaScript `eval`.
- This is a self-administered review. For production or regulated use, have an independent reviewer repeat it.
